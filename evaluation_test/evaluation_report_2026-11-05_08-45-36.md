## What is measured and against what

The 32 public samples are the only cases with reference answers (`dataset/sample_output.csv`), so every accuracy number is on those 32. The 518 evaluation requests have no reference answers; for them the report only checks the output against the submission contract.

## Known limits

* There is no reference answer for the evaluation requests, so accuracy on them is not measured.
* Where the engine cannot prove which case a resource belongs to, it leaves the step out instead of guessing. This lowers recall, never precision.
* Cases with no identifiable resource are answered COMPLETE with no steps and are listed above.
* The `condition` column of `deletion_rules.csv` is not evaluated; the engine uses the required action per data category.
* Every row is decided by deterministic code; the run itself calls no model. A few resource states come from stored readings of console screenshots (`code/readings/`), which a model made by viewing the images. The loader checks each reading against the evidence, and a reading only fills in the state of a resource that identifiers already tie to the case.
* The stored readings could not be checked against reference answers: none of the public samples involves them. They are checked only for consistency with the evidence.
